# Makezaa repository guide

## Project

This is Makezaa's Next.js App Router website. The canonical public origin is https://www.makezaa.com. The application lives in `app/`, shared UI in `components/`, and business/content helpers in `lib/`. `kota-clone/` is reference material, not the production application.

## Public search and AI discovery

- `app/robots.ts` generates `/robots.txt`. Keep public pages and rendering assets accessible. Apply the complete shared policy to every named crawler because named groups do not inherit wildcard rules.
- Preserve `/api/` and `/private/` crawling exclusions. Admin/auth/todos must remain crawlable to read their existing noindex directives. Authentication protects private data.
- `app/llms.txt/route.ts` and `app/Agent.md/route.ts` serve public discovery documents generated by `lib/ai-discovery.ts`. Keep them anonymous and independent of CMS/database availability.
- Service descriptions and anchor IDs come from `lib/service-catalog.ts`; contact details come from `lib/nav-links.ts`; canonical origin and organization facts come from `lib/seo.ts`. Reuse these sources rather than inventing facts or duplicating service catalogs.
- Public detail pages and the sitemap include only published content. Do not expose drafts, inbox messages, customer submissions, credentials, or internal task reports in discovery documents.
- Keep the existing design, URLs, redirects, canonical metadata, and structured data consistent. Cite actual pages; do not invent certifications, ratings, clients, performance results, or SEO guarantees.
- This repository guide is for coding contributors. The public `/Agent.md` is a separate reading guide, not an authorization mechanism.

## Validation

Use the existing package scripts and dependencies. For crawler/discovery changes, run:

```sh
node --test tests/seo.test.cjs tests/public-content.test.cjs tests/admin-auth.test.cjs tests/agent-control.test.cjs
npx tsc --noEmit
npm run build
```

The Next.js build currently ignores TypeScript errors, so run the type check separately. Verify the rendered discovery endpoints and HTTP headers against a local production server. Report any failed checks honestly. See `docs/seo.md` for SEO behavior and `docs/dokploy.md` for deployment details. Pushing to `main` triggers the existing deployment workflow.
